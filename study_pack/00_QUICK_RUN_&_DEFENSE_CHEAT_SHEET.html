🌬️ 4. The Apache Airflow "Kitchen Manager" Speech (30 Seconds)

When your mentor asks: "How does Airflow work here and why not just use a Python script?"

Read this verbatim:

"Imagine a restaurant kitchen: Chef 1 chops the vegetables (Ingestion), Chef 2 makes the sauces (RFM Features), the Master Chef cooks the steak (Machine Learning), and the Waiter delivers the plate (Alerts & Power BI).

Airflow is the Kitchen Manager. It doesn't do the cooking itself; it orchestrates the workflow.

In dags/retainiq_pipeline_dag.py, Airflow runs our 4 tasks every morning at 6:00 AM UTC using the TaskFlow API (@dag, @task). It enforces strict one-way dependencies: ingest >> rfm >> infer >> alert. If Task 1 fails due to a database timeout, Airflow pauses, automatically retries after 5 minutes, and prevents downstream machine learning from running on corrupted data.

Notice that we strictly followed the Database Pushdown Pattern: heavy data stays inside SQL, and Airflow XComs only pass lightweight operational audit metadata."

🎯 5. Top 6 Killer Interview Answers (Cheat Sheet)

Q1: "How does your pipeline handle incoming batch or streaming data without corrupting historical baselines?"

Answer: "We engineered a dual-mode ingestion architecture in src/etl/ingest.py. Standard runs ingest our benchmark baseline, while passing --simulate triggers simulate_incoming_batch(). It reads the latest MAX(customer_id) from SQL, synthesizes an incremental batch of new customer transactions with realistic early-tenure complaint signals, appends them to SQL, scores them with our Random Forest model, and triggers real-time alerts. Furthermore, our --reset switch allows restoring the pristine baseline in 2.4 seconds."

Q2: "Why did you make Power BI a 1-page dashboard instead of multiple tabs?"

Answer: "To prevent cognitive overload for executive leadership. We followed a 1-page 'Single-Pane-of-Glass' design: Row 1 gives high-level portfolio KPIs (5,630 accounts, 86.3% retention, 339 high-risk), Row 2 diagnoses root causes (category churn and 70-month tenure decay curve), and Row 3 provides an unsummarized daily tactical action queue sorted by highest churn risk."

Q3: "Why optimize for Recall instead of Accuracy in the ML model?"

Answer: "In churn prediction, datasets are imbalanced (~14% churn). A naive model predicting 'No Churn' for everyone gets 86% accuracy while catching zero churners! A False Negative (missing a leaving customer) loses hundreds of dollars in customer lifetime value. A False Positive (giving a discount to a loyal customer) has minimal cost. Therefore, we tuned class weights and thresholds specifically to maximize Recall."

Q4: "Why do you have RFM feature engineering?"

Answer: "Raw columns like '10 orders' don't tell the full story. A customer who ordered 10 times two years ago is different from someone who ordered 10 times this week. RFM quintiles (1–5) capture customer velocity across Recency, Frequency, and Monetary dimensions, giving the Random Forest model strong behavioral signals."

Q5: "Why did you push transformations into SQL Views instead of Power Query?"

Answer: "In enterprise data architectures, the golden rule is 'Transform upstream, visualize downstream.' By executing joins, CASE statements, and RFM aggregations directly in SQL views on the database engine, we leverage indexing and query plans. This keeps the Power BI data model lightweight and enables sub-2-second live refreshes."

Q6: "How do you prove your code actually works?"

Answer: "We built a complete automated integration test suite in tests/test_pipeline_e2e.py. Running python -m pytest tests/test_pipeline_e2e.py -v runs 7 end-to-end tests across schema, ingestion, RFM math, ML inference, alerts, and Power BI CSV exports in 4.10 seconds with 100% pass rate."
